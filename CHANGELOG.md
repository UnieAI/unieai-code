# Changelog

What changed in each release of UnieAI Code (`@unieai/code`, the `unieai`
binary), newest first. Releases are the `npm-v*` tags of this repository.

UnieAI Code is a fork of [openai/codex](https://github.com/openai/codex). This
file lists only UnieAI's own changes; when a release brings in upstream Codex,
it says how far. Upstream's own changes are listed on the
[openai/codex releases page](https://github.com/openai/codex/releases).

"uac" is the UnieAI agent engine (unieai-agent-core, on rabi-harness),
the default since 0.0.28; "codex" is the original engine. Switch with `/engine`.

## 0.0.47 — 2026-11-26

- Merged upstream Codex through
  [`3f65e9f131`](https://github.com/openai/codex/commit/3f65e9f131) (2026-11-25).
- Rabi Harness 換到 Rabi 0.2.2-rc.5（由 dsh 0.2.2-rc.5 發佈）。

### New

- **思考會出現在畫面上，預設折疊成一行。** 每段思考在歷史紀錄裡顯示第一句（灰色
  斜體，句尾 `(ctrl+t)`），完整內容在 transcript（`Ctrl+T`）。以前思考只放在
  transcript，模型只在思考裡說明自己在做什麼時，畫面上就只剩一串沒有任何說明的
  工具呼叫。
- **`/mcp callback <url>`：瀏覽器在另一台電腦也能完成 MCP 登入。** 登入時一定會印出
  授權網址；瀏覽器跳轉到 `http://localhost:…/callback` 卻連不到這台機器時，把那個
  網址貼回 `/mcp callback`，就會轉交給本機正在等的登入。會先檢查 state、主機、
  連接埠與路徑，對不上就拒絕。
- **MCP 登入等候時間可以調整，callback 頁面也不再亂報成功。**
  `mcp login --timeout-secs` 或設定檔的 `mcp_oauth_login_timeout_secs`（預設 300 秒）；
  state 不符時頁面顯示失敗，不再顯示「Authentication complete」。說明見
  [docs/unieai/login.md](docs/unieai/login.md)。
- **commit 與 PR 會標成 UnieAI Code 協作（Rabi Harness）。** commit 結尾加
  `Co-Authored-By: UnieAI Code <rabi@unieai.com>`，PR 說明預設加
  「🤖 Generated by UnieAI Code」。可以在 `config.toml` 的 `[attribution]`
  用 `commit`／`pr` 改寫或設成空字串關掉。

### Improved

- **resume 快很多。** 125 個回合的大 session 從約 10 秒降到約 4.8 秒（server
  剛啟動）或 0.7 秒（server 已在跑）；中型 session 從約 6 秒降到 2.8／0.45 秒。
  歷史改成分頁載入，只讀畫面要顯示的回合；讀過的歷史有快取；第一個畫面不用再等
  session 開啟與 MCP 連線。
- **TUI 版面跟 codex 一樣。** 常駐的待辦／subagent 面板改成選用
  （`[tui] agent_tree = true` 才開），預設用 codex 的計畫卡與 agent 切換方式。
- **開 session 更快。** 多台 MCP 伺服器同時檢查登入狀態，不再一台等完換下一台；
  Rabi 啟動使用 Node 的編譯快取，每次約省 0.6 秒。

### Fixed

- **OAuth 登入的 MCP 伺服器（例如 UnieAI Space）在 Rabi Harness 下終於用得到。**
  以前 token 沒有傳進引擎，伺服器直接被略過，模型拿不到工具，只好自己去猜 resource、
  甚至自己寫 OAuth。現在用 `/mcp` 登入一次就能在每個 session 使用，token 快到期時
  會自動更新（只由一個地方更新，不會撞到 Space 的 refresh token 輪替）。
  沒登入的伺服器會提示執行 `/mcp login <name>`。
- **resume 後的工具卡顯示輸出了。** 以前每個工具都停在「執行中」、沒有輸出
  （Rabi 0.2.2 改了工具結果的格式）。
- **codex 引擎的 subagent 收得到任務了。** 用 UnieAI 等非 OpenAI 的 provider 時，
  `spawn_agent`／`send_message` 交給 subagent 的文字是加密格式，只有 OpenAI 讀得懂，
  轉換時被整段丟掉，subagent 收到的是空任務。現在非 OpenAI provider 改用明文。
- **核准卡顯示要核准的內容。** 改檔案的核准卡會顯示 diff；執行指令的核准卡顯示
  那行指令，不再是一整串 JSON；MCP 工具顯示工具名稱與參數。

- **等指令跑完時插話，模型會馬上看到。** 以前模型輪詢一個長指令（build、測試）時
  最多等 300 秒，期間你說的話要等它等完才送到；現在一插話就停下來讀，指令照樣在背景跑。
- **peer 工具不再跑錯視窗，也不會再卡住整個 session。** 同一個 session 開在兩個視窗、
  或最早的視窗已經切到別的 session 時，`list_peers`／`send_peer_message` 會在錯的視窗
  執行（清單裡出現自己、聯絡不到別人），甚至沒有回應、中斷也停不下來，之後每次送出都是
  「a prompt is already in flight」。現在由你正在打字的視窗執行，中斷一定會結束它。

### Rabi Harness

- **上下文壓縮不再那麼頻繁。** 128k 視窗以前在約 65k 就壓縮（設定被一個為 1M
  視窗設計的預設值蓋掉），現在照設定在 75% 才壓縮；64k 以下的視窗以前根本不會
  自動壓縮。大型工具輸出改存檔案（spill）的設定也重新生效。
- **MCP 工具很多時改成按需載入。** 工具定義超過上下文 10% 時（Space 的 118 個工具
  約 2.7 萬 token），先藏在 `tool_search` 後面，用到才載入。
  `UNIEAI_TOOL_SEARCH=off|on|auto:<百分比>` 可以調整。
- **更會分派 subagent。** 提示詞說明什麼時候該平行分派（獨立的子任務、大範圍搜尋、
  驗證）、什麼時候自己做，以及怎麼交代任務。
- **做事前會先說一句在做什麼。** 提示詞明確告訴模型使用者看不到它的思考。
- 畫面上的「uac」都改叫 Rabi Harness（`/engine rabi`；舊名 `uac` 仍可用）。

## 0.0.46 — 2026-11-23

### New

- **思考強度（reasoning effort）現在真的調得動。** 選到支援的模型時，`/model`
  會多一層七個等級（`none`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`），
  也可以在對話中按 `Alt+.`／`Shift+↑` 提高、`Alt+,`／`Shift+↓` 降低，或寫進
  `~/.unieai/config.toml` 的 `model_reasoning_effort`。以前這個旋鈕完全不出現：
  沒有任何一層告訴模型清單「這個模型有哪些等級」，rabi 就不提供這個選項。
  現在 gateway 有宣告就用它宣告的（`reasoning_levels`／`reasoning_efforts`），
  沒宣告時 DeepSeek V4 系列按家族補上；其他模型仍然不顯示，而不是送一個會被
  忽略的參數。選到模型沒有的等級時，engine 只寫一行 log 並保留原本的等級，
  不會讓整個 turn 失敗。說明見 [docs/unieai/reasoning.md](docs/unieai/reasoning.md)。
- **uac 的「Thinking」區塊現在有內容了。** rabi 一直都在送思考文字，但被放進
  reasoning 項目的 `content` 欄位——那是只有 `show_raw_agent_reasoning = true`
  才顯示的原始 CoT 通道（預設關），而畫面上收合的 Thinking 區塊讀的是 `summary`
  與 `item/reasoning/summaryTextDelta`。現在思考文字走 `summary`，模型在回合中間
  的旁白仍照舊即時出現在工具卡上方。
- **找得回以前的對話：跨 session 全文搜尋。** uac 多了六個工具——
  `session_search`（同一個 workspace 裡的歷史對話，每個 session 回一個最相符的事件與標題）、
  `session_event_search`／`session_event_read`／`session_event_trace`（單一
  session 內的事件與血緣）與 `session_trace`。索引是第一次搜尋時才對既有的
  session 檔現建的（`openAt: first-search`），平常不佔記憶體，也不會在你的
  session 目錄留下額外檔案；範圍限於同一個 workspace。問「上次那個
  callback 是怎麼修的」不必再自己翻記錄。
- **`ralph`：可以放著長跑的工作流。** 給它一個不變的目標，它會一輪一輪
  開全新的子代理去做（每輪換一個乾淨的 context，共享的只有 workspace，
  最多 64 輪），直到某個子代理回報完成、回報卡住、或到達上限才停；中途
  每一步都照常出現在對話裡，也能隨時打斷。適合「跑到測試全綠」這類
  沒有固定步驟的收尾工作；同一個 session 內的長跑仍用 goal 系列。
- **`/debug-m-drop` 真的會清掉記憶。** 以前只印一行空殼訊息；現在兩個引擎都
  走 `memory/reset`，成功時回「Reset local memories.」，失敗時把原因說出來。

### uac engine

- **`none` 現在真的等於「不要思考」。** codex 的等級名稱 `none` 會轉成 rabi 的
  `off`，送給 gateway 的值是 `"none"`。在這之前 uac 把 `off` 當成「這個參數不要
  送」，等於用供應商預設值 —— 模型照樣會想。
- **引擎改名為 Rabi Harness。** `/engine` 選單、`/context` 與狀態列一律顯示
  `Rabi Harness (uac)`，說明文字改成 `rabi-harness over ACP`。引擎 id 仍是
  `uac`，`rabi`、`rabi-harness`、`unieai-agent-core` 也都還能打。
- **`ptc` 與 `creator`（cordis）從引擎選單移除。** 這兩個模式要有 rabi web app
  的 cordis 檢視才有意義，走 ACP 時只有一個空殼；手動寫在模式檔裡仍然有效。
  舊設定停留在這兩個模式時會自動回到 `standard`，不會卡住。

### Improved

- MCP 的說明改指向本專案自己的 [docs/unieai/mcp.md](docs/unieai/mcp.md)
  （原本指向上游 codex 的文件，內容對 `~/.unieai/` 不成立）；`unieai mcp list`
  在完全沒有設定 server 時會直接說怎麼加第一個。
- 在 codex 引擎打 `/loop` 不會再被當成一句普通訊息送給模型：它會說明這個
  指令要 rabi 引擎（`/engine` 切換）。uac 上不受影響。
- **401 不再是只有一句 `invalid_api_key`。** 當 gateway 拒絕這台機器的 key
  （`401 invalid_api_key`／`invalid_token`），uac 會先說清楚是哪一個 gateway
  拒絕、這台機器登入的是哪個產品、該跑哪一個指令修好（`unieai login sync`、
  `unieai login`，或把 Studio 的 key 送到 Rabi 端點時要 `unieai login --rabi`），
  再附上 rabi 原本的錯誤字串供回報；它不會被當成用量上限，也不會假裝會重試。

## 0.0.45 — 2026-11-22

### New

- **`unieai mcp login` can finish an MCP server's OAuth sign-in when the
  browser runs on another machine.** Add `--remote` and Code asks Rabi for a
  short-lived rendezvous instead of listening on a localhost port: the terminal
  prints one link, you authorize in any browser you already have open, and the
  waiting command completes by itself — no pasting a callback URL, no SSH port
  forwarding, no tunnel. The PKCE verifier, the state and issuer checks, the
  token exchange and the stored MCP credential all stay in Code; Rabi only
  carries the authorization code, and it never sees your account token or the
  MCP request headers. One sign-in lasts at most 10 minutes, Ctrl-C cancels it,
  and `--remote-url` points the rendezvous at a self-hosted Rabi. Without
  `--remote` nothing changes.
- Needs the matching Rabi build: `/api/mcp/oauth/remote/*`, and an MCP
  authorization server that names `iss` in its authorization response and
  supports dynamic client registration (or a client registered for the public
  callback). Remote mode cannot be combined with
  `--oauth-client-registration cimd`, and it says so instead of trying.

## 0.0.44 — 2026-11-22

### Improved

- **A Rabi plan shows the allowances it actually has: a 5-hour window and a
  rolling week.** `/usage` on a Rabi sign-in draws those two — used and limit
  in model-cost USD, and when each resets — and the status line's 5-hour and
  weekly items fill in from the same numbers. A window that runs out warns once
  in the conversation, like Studio's does. The six per-feature gauges (vision
  pages, agent sessions, agent tokens, chat tokens, MCP calls, tool calls) are
  retired and no longer shown: no plan capped them, and nothing was charged
  against them.
- When the allowance belongs to UnieAI Studio, or the machine has no account,
  `/usage` says who meters it instead of drawing an empty Rabi meter.
- Needs the matching Rabi build: `GET /api/desktop/usage` now answers a
  `windows` block. Until Rabi serves it, `/usage` reports that this Rabi does
  not offer plan usage yet rather than claiming the plan has no limit.

## 0.0.43 — 2026-11-21

### New

- **`unieai kube` — kubectl for UnieAI Studio vClusters.** After `unieai login`
  (Studio), `unieai kube kubeconfig <vCluster>` writes a kubeconfig that holds
  no secret: kubectl runs `unieai kube token`, which exchanges your Studio
  sign-in for a 15-minute token for that vCluster, caches it (owner-only) and
  renews it before it expires. Access follows the roles assigned to you in the
  vCluster's project, and stops within 15 minutes of being revoked. CI uses a
  project machine identity key in `UNIEAI_MACHINE_KEY` instead of a sign-in.
  `unieai kube logout` (or `unieai logout`) clears cached tokens. See `docs/unieai/kube.md`.

## 0.0.42 — 2026-11-20

### Fixed

- **Windows: leaving Full Access.** On Windows, once a uac session was set to
  Full Access, choosing Default again only printed "Windows sandbox setup
  requires local connections and executors" and the permissions stayed on
  Full Access. uac sessions now tell the TUI that the uac engine confines

## 0.0.41 — 2026-11-20

### Fixed

- **Rabi sign-ins work again.** Rabi moved to https://rabi.unieai.com. The old
  address redirects there, but the redirect dropped your login, so requests
  failed with 401. UnieAI Code now uses the new address, and a login saved
  against agent.unieai.com is moved to it when it loads; you do not need to
  sign in again. Remote Control uses the new address too.

### uac engine

- **uac runs on Rabi,** UnieAI's build of the agent harness (`@unieai/rabi`,
  rabi-harness 0.2.1-rc.3; same code as before, new names). Your sessions,
  settings and attachments move from `~/.unieai/uac/dsh-home` to `rabi-home`
  on first start, and older conversations resume as before. If an older
  UnieAI Code is still open, the move waits until it closes; resuming a
  conversation that is still open there asks you to close the older window
  first. `DSH_HOME` and `UNIEAI_DSH_*` keep working; the new names are
  `RABI_HOME` and `UNIEAI_RABI_*`.

## 0.0.40 — 2026-11-18

### Fixed

- **uac runs on Windows.** On Windows the uac engine never started, so every
  session fell back to codex; the server log showed
  `listen EACCES: permission denied …\uac\app-server.sock`. Node cannot
  serve a Unix socket on Windows, so there the uac server now listens on a
  loopback port (127.0.0.1) that only accepts clients presenting a random
  token. The token is kept in your own `uac` directory. rabi's control channel
  uses a named pipe there. macOS and Linux keep using Unix sockets.

## 0.0.39 — 2026-10-24

A fix release for 0.0.38, which could not start the uac engine on any
install.

- Merged upstream Codex through
  [`970111f6cb`](https://github.com/openai/codex/commit/970111f6cb) (2026-10-23,
  124 commits). Notable: a model the provider does not have now fails the turn
  instead of being retried, reasoning-effort overrides are on by default,

  prompts in the background transcript are grouped, retained reasoning is no

### Fixed

- **uac starts again.** The 0.0.38 package left out a module the uac server
  imports, so uac died at launch with `ERR_MODULE_NOT_FOUND` and the session
  fell back to codex. On a Rabi account that showed up as
  `404 Not Found … /api/desktop/v1/responses`, since Rabi serves only chat
  completions. The release build now fails if a shipped module imports a file
  that was left out.
- **Windows reports its real version.** Windows builds always reported
  `0.0.22-dev-uc0.5.0-ac0.4.0`, whatever the release, so updating seemed not
  to work and the update notice kept coming back.
- **The welcome logo stays.** A warning shown at launch (such as uac not
  starting) no longer clears the logo a moment after it appears.

## 0.0.38 — 2026-10-22

- Merged upstream Codex twice: through
  [`66d0de9983`](https://github.com/openai/codex/commit/66d0de9983) (2026-10-20,
  106 commits) and through
  [`067249a283`](https://github.com/openai/codex/commit/067249a283) (2026-10-21,
  35 commits). Notable: `$` mentions rank by what you picked recently, async
  question prompts render as Markdown, Up recalls the prompt given on the
  command line, `/permissions` holds queued prompts until its menu is open,
  the model list is kept when a refresh fails, and a thread keeps its model
  settings when resumed. The Rust toolchain is now 1.99.1.

### New

- **`/usage` for UnieAI Studio plans.** Without a ChatGPT login, `/usage`
  shows your Studio plan: the 5-hour and weekly windows (% used and when they
  reset), extra usage with a switch that asks before it bills API credits,
  credit grants and when they expire, and your wallet with its monthly limit,
  plus Manage plan and Top up credits links. Plan usage also feeds `/status`,
  the composer's usage notice and the 5-hour / weekly status-line items, on
  both engines. Studio spends grants first, then the plan windows, then (with
  extra usage on) the wallet.
- **`/tasks`** (also `/ps`) lists subagents and commands left running in the
  background, with status, run time, tokens, model and last action. Open one
  to see its transcript or recent output, or stop it.
- **Remote Control (uac, preview).** `/remote-control` and
  `unieai remote-control [start|stop|devices|revoke]` show a pairing link and
  QR code so a browser can follow a session, send prompts, answer approvals
  and questions, and interrupt. The connection is end-to-end encrypted: the
  relay only passes ciphertext. While it runs, the status line shows
  "Remote: N viewers". UnieAI's hosted relay is not live yet, and
  `/remote-control` says so. Until it is, Remote Control needs a relay you
  run yourself: `unieai remote-control start --relay <URL>`, or set
  `UNIEAI_REMOTE_RELAY_URL`.
- **Artifacts (uac, preview).** The agent can publish a web page to your
  UnieAI Rabi gallery with `publish_artifact`, and update the same page in
  place when it publishes from the same path again. A bundled artifact skill
  tells it how. `unieai artifact list | open | delete | publish | set` does
  the same from the shell. Artifacts need a Rabi sign-in, and depend on
  Rabi's Artifacts service, which is still rolling out.

### Improved

- The agent tree under the composer shows only live work: running
  subagents, ones waiting on you, failed ones you have not seen, and commands
  still running. Finished work moves to `/tasks`, and a dim
  "N done · /tasks" line counts it. `[tui] agent_tree_show_finished = true`
  brings back the old panel.
- In the agent tree, `o`/Enter opens a subagent or background command, `x`
  stops it after asking, and F6 focuses the tree. Rows show each agent's
  model.
- Commands UnieAI Code cannot serve yet now say "coming soon" instead of
  failing or disappearing: `/app`, `/voice` and `/apps` (unless the provider
  is OpenAI's), `/feedback` without a `[feedback] webhook_url`; and on uac
  `/review`, `/side`, `/btw`, `/memories`, `/plan`, `/hooks`, `/plugins` and
  `/approve`. They are marked "(coming soon)" in the `/` popup.
- `/status` shows a Studio wallet as available credits.

### Fixed

- uac no longer fails every turn with "ACP agent closed the connection" on
  Node 23, Node 22 before 22.18 or Node 24 before 24.2. The engine now starts
  on those versions.
- When the uac engine dies at startup, the error now says how (exit code or
  signal). On macOS, a kill at startup comes with the `xattr` command that
  clears the download quarantine.
- Plan-limit and billing refusals from the UnieAI gateway (out of balance,
  wallet monthly limit, plan window used up) now say what to do (top up,
  raise the limit, or turn on extra usage in `/usage`, with the reset time)
  and are no longer retried. This applies on both engines.

### uac engine

- Several clients can watch one thread: every client gets its updates,
  approvals and questions go to all of them with the first answer winning,
  and a second TUI on the same thread no longer takes over the first one's
  approvals and tools.
- Subagents can be stopped. Commands left running are reported as
  background terminals that can be listed, read and stopped. Each subagent
  reports its own token usage.

### Login & models

  mode: a reviewer model answers the session's approval requests and only
  risky ones reach you. `UNIEAI_AUTO_APPROVAL_MODEL` picks a cheaper
  reviewer model.
- **Background commands report their exit (uac).** When a shell session left
  running in the background exits, the model gets its exit code and unread
  output. If a turn would end while its own build is still running, it waits

  instead of the OpenAI blossom.

  its tools, such as the peer tools.
- Reading another session's thread (`wait_threads`, `read_thread`, `/context`,

  approvals.
- Rewind no longer fails with "thread history changed" or cuts the wrong
